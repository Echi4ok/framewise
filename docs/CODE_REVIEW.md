# Архитектурное ревью

Ревью 6 ноября 2026 года охватывает рабочий frontend, backend, интеграцию с VLM, запуск и Docker-конфигурацию. Изменения сохраняют HTTP-контракт, модель, инструкции и исходные данные. Исторические R&D-результаты не пересчитывались и не выдаются за измерение новой конфигурации.

## Границы ответственности

| Слой | Ответственность | Основные файлы |
|---|---|---|
| UI | Поля, галерея, управление выбором, связанные рамки | `frontend/src/components/` |
| Сценарий UI | Draft, запросы, отмена, время ожидания, сброс и навигация | `frontend/src/composables/` |
| Клиент API | HTTP, ошибки, проверка полученных JSON и допустимых IDs | `frontend/src/services/` |
| Представление текста | Инертное преобразование описания HTML в обычный текст и единая пунктуация UI | `frontend/src/presentation/` |
| HTTP API | Входные формы, DTO, зависимости, ответы и преобразование AppError | `backend/app/main.py`, `http_limits.py`, `schemas.py` |
| Сценарий приложения | Импорт товара, выбор и анализ, дедлайны, срок жизни данных | `backend/app/services.py` |
| Домен | Неизменяемые значения товара, фотографии и подготовленного изображения | `backend/app/domain.py` |
| Хранилище | Каталог, временные товары, память, TTL и leases | `backend/app/store.py` |
| Внешние ресурсы | Получение и подготовка изображений, ограниченные workers, VLM API | `images.py`, `workers.py`, `model.py` |

`App.vue` связывает экран с composables. UI не выполняет HTTP и не управляет временем жизни blob URL. Серверный домен и хранилище не импортируют FastAPI. Приложение зависит от контракта `VisionGateway`, а конкретный SDK создаётся в lifespan. `AsyncExitStack` закрывает принадлежащие приложению ресурсы также при ошибке запуска.

## Подтверждённые дефекты и исправления

| Дефект | Исправление и проверка |
|---|---|
| Один App.vue управлял UI, сетью, файлами и таймерами | Сценарий и время жизни ресурсов вынесены в composables, HTTP в сервисы; компоненты получают props и отправляют события |
| Ответ завершившегося запроса мог попасть в уже закрытый экран | AbortController, проверка актуальности запроса и очистка при unmount; регрессии позднего ответа и повторного запуска |
| Одна недоступная демонстрационная карточка скрывала остальные | Независимое получение и сохранение доступных примеров, возможность повторить загрузку |
| Разные файлы с одинаковыми именем, размером и mtime считались одинаковыми | На клиенте повторно не добавляется только тот же File-объект; точная дедупликация содержимого принадлежит серверу |
| Частичная ошибка выделения preview URL оставляла ресурсы | Атомарное добавление и освобождение уже выделенных URL |
| Тип `request<T>` утверждал корректность неизвестного JSON | HTTP возвращает unknown, предметный сервис проверяет DTO, рамки и принадлежность IDs |
| Новые координаты или ошибка старого снимка могли появиться поверх другого кадра | Рамки показываются после load соответствующего src/currentSrc; img привязан к ID кадра. Запоздалые load/error игнорируются, успешная загрузка очищает ошибку |
| Таймаут SDK не ограничивал очередь и сумму попыток | Один бюджет операции включает очередь, основной ответ и один repair |
| Число потоков ограничивалось, но отменённые ожидания могли оставлять WorkItems с большими bytes в executor queue | Permit берётся до submit и удерживается до фактического завершения concurrentFuture. Shield отделяет отмену ожидания от времени жизни работы; регрессия проверяет число submit до освобождения занятого worker |
| Неожиданная структура ответа провайдера падала до валидации | Отдельная проверка envelope перед доступом к choices, message и usage |
| Не было общего дедлайна URL-импорта | Дедлайны отдельного URL и всей подготовки товара; проверка медленного потока и нескольких ссылок |
| Multipart разбирался до ограничения общего запроса | Admission и лимит тела перед парсером, лимиты JSON и времени чтения, управляемые 413/503/504 |
| Закрытый клиент мог оставлять выполняющуюся операцию и занятые очередь/lease | ASGI disconnect отменяет обработчик, отмена распространяется в SDK, ресурсы освобождаются через finally. Регрессия проверяет отмену и освобождение lease |
| Общий клиент URL-импорта мог хранить cookies по pinned IP и передавать их другому исходному hostname | Cookie policy запрещает сохранение и отправку cookies; проверены два origin с одним IP |
| Keepalive-соединение по pinned IP могло обойти новую SNI/certificate-проверку другого hostname | Для image client отключены keepalive и HTTP/2. Регрессия проверяет реально переданные параметры client factory |
| Health мог раскрыть credentials и query-ключи из MODEL_BASE_URL | В публичном provider URL удаляются userinfo, query и fragment; проверен URL с тестовыми секретами |
| Срок хранения очищался только при новом обращении | Периодическая очистка с сохранением lease активной операции |
| Ошибка чтения каталога оставляла частичное состояние | Каталог собирается отдельно и публикуется атомарно |
| Исключение в lifespan могло пропустить закрытие SDK и клиентов | AsyncExitStack закрывает owned resources, workers и задачу очистки также при исключениях; store очищается при остановке |
| Скрипт остановки оставлял дочерний uvicorn | Проверка идентичности процесса и его дочернего дерева, безопасная работа с занятыми портами и откат неудачного запуска |
| Build context мог включить локальное окружение | Исключение `.env` и runtime; контейнеры приложения запускаются без root |
| Раскрытие формы сдвигало примеры слева | Для первой строки Grid задан max-content: высота правой формы не меняет положение примеров. Измеренный сдвиг до правки около 114 px, после правки 0 px |
| Автовыбор VLM был плохо заметен под всей галереей | Явная кнопка «Подобрать фото с ИИ» и пояснение перед фотографиями; тот же suggest endpoint, пользователь может изменить результат |
| HTML из CSV отображался как текст тегов | Инертный template разбирает разметку в presentation-слое, переносы и списки преобразуются в обычный текст; script/style и встраиваемый контент исключаются. v-html не используется |
| Пустой текст ошибки от внешнего API скрывал сообщение | Проверка непустого detail/message/msg и понятный fallback HTTP-ошибки |
| Повреждённые PNG могли выбросить SyntaxError или IndexError из Pillow | Неподдерживаемые метаданные дают управляемый invalid_image/422. Тесты воспроизводят оба исключения |
| Очень длинный Content-Length приводил к ValueError при int() | Общая функция сравнивает ограниченную десятичную строку с лимитом без преобразования в неограниченный integer; проверены request и URL response |
| Исключение operation прерывало finally до завершения disconnect monitor | Обе задачи отменяются до совместного gather; исходная ошибка сохраняется, фоновый receive завершается |

## Проверка backend

После повторного ревью backend выполнено **84 теста, 84 passed за 2.59 s**. Ruff check и format check прошли. Mypy завершился без ошибок для 13 app-файлов. Три новые регрессии воспроизводили дефекты до внесения исправлений.

```sh
cd backend
../.venv/Scripts/python -m pytest -q
../.venv/Scripts/python -m ruff check app tests
../.venv/Scripts/python -m ruff format app tests --check
../.venv/Scripts/python -m mypy app
```

Регрессии охватывают malformed provider envelope, общий deadline очереди и repair, медленный URL-поток и весь batch, oversized и chunked bodies, admission до чтения upload, disconnect, реальные сроки жизни workers, атомарность каталога, TTL cleanup, изоляцию cookies/TLS и очистку health URL. Внешняя VLM в этих тестах подменяется контролируемым gateway или MockTransport. Содержимое model payload и нормализованные изображения также проверяются. Фактический запуск и браузерные проверки фиксируются отдельно в `RUN_VERIFICATION.md`.

## UI и motion

После повторного ревью frontend прошли 48 тестов, ESLint без предупреждений, vue-tsc и production build. Полный браузерный сценарий выполнен с настоящей локальной VLM; доказательства и границы проверки находятся в [RUN_VERIFICATION.md](RUN_VERIFICATION.md).

Переходы основаны на просмотренных публичных примерах [Mint Noir](https://skillry.dev/skills/bs-mint-noir-saas-site) и [Slate Admin Console](https://skillry.dev/skills/bs-slate-admin-console) и сверены с [Motion for Vue](https://motion.dev/docs/vue-layout-animations). Финальная палитра изменена по обратной связи: чёрный #090b10, поверхность #151921, основной синий #0f62fe и синий текста #78a9ff. Градиенты, фоновые свечения и цветные тени убраны; выбор подчёркивается полной заливкой карточки и галочкой.

Ориентир для ролей цвета: [Carbon Color](https://www.carbondesignsystem.com/building-blocks/foundations/color/overview), нейтральные поверхности и синий для действий. [Обсуждение UXDesign](https://www.reddit.com/r/UXDesign/comments/1s1guo5/what_are_the_top_ai_slop_design_patterns/) отражает критику повторяющихся градиентов и свечений, но не устанавливает объективный способ определить происхождение интерфейса.

- Один товар и одно или несколько его фото объясняются до загрузки; технические поля скрыты.
- Изменения высоты сценария обрабатывает небольшой `MotionSurface` на ResizeObserver и Web Animations API. Слушатели и анимации очищаются при unmount.
- Состояния feedback используют постоянную область, кнопки и выбор не меняют размеры при переключении.
- Результат имеет постоянную область просмотра, относительные координаты SVG и загруженное фото остаются согласованы.
- Анимация преимущественно меняет opacity и transform. Для смены высоты измеряется одна поверхность. Scroll hijacking и сторонняя библиотека анимации не нужны.
- Учтён `prefers-reduced-motion`, в том числе его изменение во время анимации. Клавиатура и focus сохранены.
- Manrope загружается локально, лицензия OFL включена в `frontend/public/fonts/`.

## Границы решения

Это локальный прототип с одним процессом API и одной последовательной GPU-операцией. Хранилище остаётся временным, локальным процессу. Для нескольких API workers потребуются общее хранилище и общий диспетчер модели. Такие инфраструктурные компоненты не добавлены без соответствующей нагрузки и требования.

По умолчанию разрешены два импорта с телами до 161 MiB каждый. Это ограничивает память транспорта до multipart parsing; память store и декодирования учитывается отдельно. Блокирующий OS DNS/Pillow-вызов может завершиться после отмены запроса, удерживая ограниченный worker slot. Прекращение вычислений внешнего провайдера после закрытия HTTP-соединения зависит от провайдера.

Валидация ответа проверяет структуру и геометрию, а не истинность визуального утверждения. Полного контроля разнообразия ракурсов, проверки идентичности товара на разных фото и автоматической семантической проверки рамок нет. Эти ограничения R&D остаются открытыми.
