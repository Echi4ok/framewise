## Повторное ревью и плоская чёрно-синяя палитра, 6 ноября 2026

- По обратной связи удалены все CSS-градиенты и декоративные цветные свечения. Фон #090b10, панели #151921, действие #0f62fe. Выбранная карточка имеет полную синюю заливку, контрастную рамку и галочку.

- Последующий анализ выбранных кадров вернул четыре детали. Нажатие на описание замка открыло фото 7 с SVG-рамкой. Отдельно загружен один JPEG с HTML-описанием: SVG-контент исключён, entities и пункты списка читаемы, кнопка подбора недоступна с явным пояснением. - Backend: 84 теста, Ruff check/format и mypy проходят. Frontend: 48 тестов, ESLint, vue-tsc и production build проходят. Дополнительно проверены corrupted PNG metadata, огромный Content-Length и cleanup disconnect monitor после исключения приложения.

## Упрощение интерфейса

Повторная проверка через Docker на 8080 после переработки frontend:

- Стартовый экран открывается с пустой формой. Сразу указано: одно или несколько фото одного товара. URL, описание и ID скрыты в дополнительных блоках.
- Одно JPEG чемодана загружено через файловый диалог, затем «Продолжить» и «Найти детали на 1 фото». Реальная локальная модель вернула три описания и рамки. Нажатие на описание 2 выделило соответствующую область.
- Два JPEG добавлены вместе. Один удалён и выбран повторно: оба превью сохранились, API подготовил два снимка, оба отмечены для анализа.
- «Другой товар» очищает название, файлы и предыдущий результат. Кнопка продолжения недоступна без фотографий.
- Пример чемодана открывает восемь кадров. Пятый кадр нельзя добавить к четырём выбранным, при нулевом выборе анализ недоступен. Автовыбор отметил 1/3/7/8; снятие 8 оставило 1/3/7 без запуска анализа.
- ID из пробелов даёт понятную ошибку без запроса к коллекции. Ошибка автоматически прокручивается в видимую область.
- На ширинах 1089 и 390 px DOM не имеет горизонтального переполнения. Изображение и SVG на desktop имеют размер 360×480, на 390 px — примерно 286.4×381.9; расхождение менее 0.02 px. Снимок мобильной эмуляции в IAB обрезал desktop surface, поэтому не используется как визуальное доказательство.
- TypeScript/Vite build и пересборка Docker frontend прошли. Консольных ошибок в браузере не обнаружено.

Это проверка сценария и геометрии UI, а не новая оценка качества модели. В ответе про колёса модель указала четыре, хотя на данном ракурсе различимы два. Интерфейс сохраняет предупреждение о проверке результатов человеком.

Для подготовки кэша в Docker volume `product-vision_models` скопированы только blobs из завершённого Ollama-манифеста 8B и сам манифест. Источник — локальный каталог `work/vision-poc/models`, использованный при сравнении моделей. Частичные загрузки и файлы `.range` исключены. Обычный первый запуск на другой машине скачивает модель из реестра.

Повторяемый API-прогон доступен в `scripts/verify-api.py`. Он обращается к реальному API модели, сохраняет сырые JSON-ответы и длительность каждого запроса в `report.json`. Проверка схемы, идентификаторов и координат выполняется автоматически. Точность описаний и расположения рамок проверяется визуально.

```sh
python scripts/verify-api.py --base-url http://127.0.0.1:8080 --output verification/api
```

## Восстановление Docker на машине проверки

Docker Desktop завершал запуск на создании внутреннего AF_UNIX endpoint `dockerInference`. Лог содержал `initializing Inference manager` и `The file cannot be accessed by the system`. `fsutil reparsepoint query` подтвердил Windows error 1920 у этого нулевого ReparsePoint. Схожая ошибка описана в [Docker issue #531](https://github.com/docker/desktop-feedback/issues/531).

После остановки зависшего Desktop командой `docker desktop stop --force --timeout 20` служебные каталоги переименованы с сохранением содержимого.

- `%LOCALAPPDATA%\Docker\run` сохранён как `run.stale-20261105-132201` в том же каталоге.
- `%LOCALAPPDATA%\docker-secrets-engine` сохранён как `docker-secrets-engine.stale-20261105-132201` в том же каталоге.
- Исходный `settings-store.json` сохранён за пределами репозитория как `docker-settings-before-20261105-132201.json`.
- В настройках Docker Desktop изменён один параметр `EnableDockerAI` с `true` на `false`.

После повторного запуска Desktop `docker info` вернул версию сервера 29.2.1, `docker ps` выполнился успешно. Отключённая функция Docker AI относится к Desktop. Модель проекта запускается отдельным сервисом Ollama.
